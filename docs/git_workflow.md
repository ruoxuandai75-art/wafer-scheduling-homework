# 通过提问学习Git操作

第一周按 [Windows 学习指南](week01_windows.md) 的第08节完成。你已经从师兄模板创建个人仓库并完成 clone，先核对实际分支与 `origin`。

## 先把状态讲清楚

向 AI 提问：“我在 Windows 的个人仓库[路径]完成了[实际文件]。请先指导我检查目录、分支、远程和改动，再一步一步教我保存、暂存、commit、push。解释每步发生在本地还是远程，让我先预测再操作。只提交本次答案与附件，不提前改后续代码。”

每次只执行已理解的一步，并把实际输出反馈给 AI。Git 姓名与邮箱配置的用途、作用范围和隐私邮箱，也请 AI 结合现状说明。

## 操作过程中的追问

- 我保存了文件，为什么网页还没变化？
- 工作区、暂存区和本地提交是什么关系？普通 diff 为什么可能看不到未跟踪的新文件？
- 我怎样查看本次暂存的具体内容，确认没有误选？
- commit 后断网，哪些内容已经保存？push 又改变哪里？
- 为什么要先确认 origin 属于自己的账号？当前分支怎么确定？
- 推送成功后，怎样在网页核对同一份提交？Everything up-to-date 能证明未保存内容也上传了吗？

Word 作业需先用 Word 或 WPS 打开核对正文，再保存并关闭。git diff 通常只能报告 .docx 是二进制文件，不能代替正文检查；结合 git status 核对本次文件，避免选择 Word 临时锁文件。

## 验收与出错时的处理

本人查看改动与暂存内容，完成 commit 和 push，在个人 GitHub 仓库中打开正确分支，确认作业文件、附件和提交编号；若 Word 不能在线预览，下载本次提交的文件打开核对答案。确认师兄可以访问。

记录实际命令与结果。失败时提供 Shell、目录、命令和报错，请 AI 先诊断；不为完成作业盲目强制推送或删除目录。克隆得到的项目不用重新初始化，第一周不强制学习分支合并与 PR。

后续周需要分支或 PR 时再向 AI 请求相应教学；把任务卡、验证结果和真实提交一起保留。
